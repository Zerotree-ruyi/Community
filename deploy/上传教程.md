## 1. 方式一:scp / rsync(推荐,一条命令)

在你 **Mac 本地终端**里执行(不是 FinalShell 里 —— 那是服务器上的 shell)。

### 1.1 先在服务器上把目录建好

FinalShell 连上 A 台,执行:

```bash
mkdir -p /www/wwwroot/trade/manager
mkdir -p /www/wwwroot/exchange-admin/admin    # B台上执行
```

### 1.2 备份旧的(强烈建议,出事了能秒回滚)

```bash
# A 台
cp -r /www/wwwroot/trade /www/wwwroot/trade.bak.$(date +%F-%H%M)

# B 台
cp -r /www/wwwroot/exchange-admin/admin /www/wwwroot/exchange-admin/admin.bak.$(date +%F-%H%M)
```

### 1.3 传

Mac 本地终端:

```bash
cd /Users/ruyi/Desktop/源码/Community

# ① 前台 → A 台
#    --delete 会清掉服务器上旧的 assets/ 和 coins/ 残留
#    --exclude 'manager/' 是必须的 —— 不然会把刚建的后台目录一起删掉
rsync -avz --delete --exclude 'manager/' \
  dist/ root@47.236.172.111:/www/wwwroot/trade/

# ② 后台 → A 台
rsync -avz --delete \
  admin/dist/ root@47.236.172.111:/www/wwwroot/trade/manager/

# ③ 后端 → B 台
#    这里绝对不要加 --delete —— 会把服务器上的 .env 删掉
rsync -avz \
  admin/server.ts admin/migrations admin/src \
  admin/package.json admin/package-lock.json admin/.env.example \
  root@47.236.95.137:/www/wwwroot/exchange-admin/admin/
```

> `rsync` 是 macOS 自带的,不用装。如果提示 `rsync: command not found`,改用 `scp`:
> ```bash
> scp -r dist/* root@47.236.172.111:/www/wwwroot/trade/
> scp -r admin/dist/* root@47.236.172.111:/www/wwwroot/trade/manager/
> scp -r admin/server.ts admin/migrations admin/src root@47.236.95.137:/www/wwwroot/exchange-admin/admin/
> ```
> `scp` 不会删旧文件(旧 assets/ 残留 = 浪费点空间,不影响运行)。

**没装 rsync / 不想用命令行**,宝塔自带的上传也行,见 §2。

## 2. 方式二:宝塔文件管理器(不想碰命令行)

宝塔 → **文件** → 顶部路径栏输入目录 → 回车 → 左上 **上传**。

| 上传哪个 | 目标目录 |
|---|---|
| `dist/` 里的全部内容 | `/www/wwwroot/trade/` |
| `admin/dist/` 里的全部内容 | `/www/wwwroot/trade/manager/` |
| `admin/server.ts`、`admin/migrations/`、`admin/src/`、`admin/package.json`、`admin/package-lock.json`、`admin/.env.example` | `/www/wwwroot/exchange-admin/admin/` |

### 手动传要注意的坑

1. **传的是「里面的内容」,不是文件夹本身。**
   进到 `dist/` 目录里 → 全选 `index.html`、`assets`、`coins`、`logo.png`、`logo.svg`、
   `lightweight-charts.standalone.production.js` → 拖进去。
   ❌ 传成 `/www/wwwroot/trade/dist/index.html` 就是白屏。

2. **宝塔上传不支持整个文件夹时**,先在服务器上建好同名文件夹,再进去逐个传文件。
   `assets/` 10 个 + `coins/` 21 个 = 31 个文件,挺烦 —— 所以还是建议用 §1 的 rsync。

3. **`index.html` 最后传。**
   它是入口,里面写着 `assets/index-xxx.js` 的文件名。
   先传 assets 再传 index.html,避免中间出现"index.html 引用了还不存在的 js"。

4. **不要传 `.env`**(B 台)。宝塔上传列表里根本没有它,别手滑传了 `.env.example` 之后
   以为 `.env` 也会被覆盖 —— 不会,`.env.example` 是另一个文件名。

## 3. 传完之后(顺序很重要)

### 3.1 B 台:跑迁移 → 重启后端

```bash
cd /www/wwwroot/exchange-admin/admin

# 迁移 —— 必须先跑!漏了 pm2 restart 会报 Unknown column 'session_token'
mysql -uroot -p zero < migrations/2026_admin_session_token.sql

# 确认 3 列都在
mysql -uroot -p zero -e "SELECT COLUMN_NAME FROM information_schema.COLUMNS WHERE TABLE_SCHEMA='zero' AND TABLE_NAME='admin_users' AND COLUMN_NAME LIKE 'session%';"

# .env 补这几个(传文件不会动 .env,得手改)
#   COOKIE_SECURE=1
#   ENABLE_HSTS=1
#   ALLOWED_ORIGINS=https://coinbase-in.com
#   ALLOW_LEGACY_ADMIN_HEADER=0

# 重启
pm2 restart exchange-admin
pm2 logs exchange-admin --lines 40        # 期望看到 "Express API ready",没有红色报错
curl http://127.0.0.1:3001/api/health     # 期望 {"ok":true,...}
```

> 本次**没有新增 npm 依赖**,所以 `npm install` 可以不跑。要跑也行,不会出错。

### 3.2 两台 nginx

- B 台:照 `deploy/nginx-bt-b-site.conf` 改 `location /api/`
  (加 `allow 47.236.172.111; deny all;` + `proxy_buffering off;`)
- A 台:照 `deploy/nginx-bt-a-site.conf` 改(两处:`/api/` 端口 3001→80、加 `/manager/` 四段)

**都是增量补丁,别整份覆盖** —— 整份覆盖会破坏 Let's Encrypt 的续签检查块。

```bash
nginx -t && nginx -s reload
```

### 3.3 验证

```bash

curl -s -o /dev/null -w "%{http_code}\n" https://coinbase-in.com/api/members/1              # 期望 403
```

确认上面全绿之后,再去 B 台宝塔「安全」+ 云厂商安全组删掉 `3001` / `3306` 的入站规则,
并把 MySQL 的 `bind-address` 改成 `127.0.0.1`。

验证(在 Mac 本地跑,连不上才是对的):

```bash

nc -z -w 5 47.236.95.137 3001 && echo "还开着!" || echo "已关 ✅"
```

## 4. 出问题怎么回滚

| 现象 | 原因 | 回滚 |
|---|---|---|
| 前台白屏 | 传成了多套一层 `dist/`,或 `index.html` 没传到根目录 | 重新用 rsync 传一次(§1.3) |
| 前台 502 | A 台 `/api/` 已改成 `:80` 但 B 台 nginx 还没配好 | 把 A 台 `proxy_pass` 改回 `:3001` |
| 后台 404 | `/manager/` 段没加,或后台文件没传到 `/www/wwwroot/trade/manager/` | 补 nginx 段 / 重传 |
| 后台登录报 `Unknown column 'session_token'` | 迁移没跑 | 补跑 §3.1 的 mysql 命令 |
| 会员接口 403 | 会员的 `session_token` 是空的,得重新登录一次 | 让会员重新登录 |
| 后端起不来 | `.env` 被覆盖/丢了 | 从 `admin.bak.*` 拷回来 |

## 5. 下次改完代码,重新生成构建产物

```bash
cd /Users/ruyi/Desktop/源码/Community

# 前台
npm run build

# 后台(必须带目录前缀,否则资源路径会指向根目录)
cd admin
VITE_BASE_PATH=/manager/ VITE_API_PREFIX=/manager/api npx vite build
cd ..

# 然后重跑 §1.3 的三条 rsync
```

> ⚠️ 后台的构建**必须带** `VITE_BASE_PATH=/manager/ VITE_API_PREFIX=/manager/api`。
> 漏了的话 `index.html` 会引用 `/assets/xxx.js`(根路径),
> 而服务器上资源在 `/manager/assets/` → 后台白屏。
> 传之前检查一眼:
> ```bash
> grep -o '"/manager/assets/[^"]*"' admin/dist/index.html
> # 应输出 /manager/assets/index-xxx.js 和 /manager/assets/index-xxx.css
> ```
